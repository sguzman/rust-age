# 🧠 Fallout 1 CE interpreter integration status

**Non-playable, source-level subset.** The reference is the pinned [Fallout 1 CE interpreter](https://github.com/alexbatalov/fallout1-ce/blob/0609bcfd0ec40ff0571d0f57fab2821eb461dc8b/src/int/intrpret.cc) and [script engine](https://github.com/alexbatalov/fallout1-ce/blob/0609bcfd0ec40ff0571d0f57fab2821eb461dc8b/src/game/scripts.cc), under the [original derivative license](../LICENSE). No commercial game scripts or data are committed.

## Implemented and verified slices

- `src/script_program.rs` parses the 42-byte .INT preamble, six-field procedure records, encoded identifier and static-string tables, and named procedure lookup. Ordinary CE `interpretFindProcedure` includes index 0; opcode `0x8028` searches from index 1 and excludes `main`. The fixed 24 built-in action slots are mapped by `src/script_procedures.rs`.
- `src/script_binding.rs` resolves serialized MAP script records through `scripts.lst` to optional installed .INT program metadata, caching repeated indices and retaining missing-program diagnostics. `--inspect-map-procedures` and `--inspect-script-index` are **read-only** commands, never game script execution.
- `src/script_vm.rs` supports a bounded subset of CE numeric, stack, branch, local-frame and procedure operations. Static-string comparisons use the original 8-bit encoded bytes and case-sensitive `strcmp` ordering, including implemented integer/finite-float formatting and opaque pointer/null equality. Heap-backed dynamic strings, string concatenation and full numeric/text coercion are not ported. Original .INT program records remain immutable; a separate runtime table stores procedure flags, timed calls, condition offsets and cancellation.
- CE `op_call_at` consumes the index before the delay and stores **milliseconds**; `op_call_condition` stores a bytecode offset. `doEvents` checks the conditional flag before timed flags. Timed triggers compare their signed stored milliseconds **as unsigned** and require `event_time < now`, not equality.
- `take_due_timed_procedures` selects only timed events. `take_due_procedures_with` also asks a supplied host condition evaluator for `Some(true)`, `Some(false)`, or `None` (evaluation did not complete). A successful true/elapsed event clears its *runtime* flags and yields its procedure index; it does **not** invoke the procedure, change world state or call Fallout's engine. Host errors leave runtime flags unchanged in this Rust subset (explicit safety guarantee, not asserted upstream behavior).
- `preview_condition_bounded` and `take_due_procedures_preview` can evaluate simple **invented** condition bytecode ending in STOP/EXIT under an instruction budget, using isolated stacks and a preserved pre-poll VM snapshot. They are diagnostic helpers, **not** CE's original mutable interpreter context/flag restoration, and cannot execute game opcodes. Malformed offsets, unsupported instructions, or budget exhaustion produce errors without consuming scheduled events.
- `src/script_runtime.rs` owns independent .INT VM instances and mirrors CE `insertProgram`/`doEvents` newest-first program traversal followed by ascending procedure-index traversal. Its suspension and registration APIs are bounded Rust adapters. `take_due_preview` bridges simple synthetic condition-bytecode previews into multi-program polling (bounded, isolated and never game-world-mutating). It returns ready program/procedure identifiers without **any** gameplay callback or native opcode invocation; seven synthetic C++/Rust differential cases verify traversal and precedence, not full production dispatch.
- `preview_local_interrupt_bounded` builds an isolated CE `setupCall`-shaped interrupt frame for zero-argument **local** procedures: old PC and CE interrupt return marker on the return stack, flags/null callback/window ID plus zero argument marker on the operand stack. Supported instruction bodies may return through `0x8025 POP_FLAGS_RETURN_VAL_EXIT`. Imports, external callbacks, real wait-function pointers, other return conventions and unsupported opcodes are rejected. The source VM's data and return stacks are unchanged; eight synthetic C++/Rust frame-unwind cases run in CI.
- `ScriptRuntime::preview_due_local_interrupts` combines source-ordered due events, synthetic condition preview and isolated local interrupt returns. This Rust-only diagnostic applies **transactional preview rollback** on error, unlike CE's nontransactional live event dispatch. Returned values are observations, not quest state or side effects. No production .INT program execution is enabled.
- `ScriptRuntime::dispatch_due_with` is an **opt-in host hook**, not an implemented Fallout engine callback. It walks each procedure in CE list order, evaluates conditional eligibility when needed, immediately clears a due procedure's runtime flags and calls the supplied host callback with a mutable Rust VM. Later condition decisions can observe earlier host callback effects; failures can leave an event consumed. This differs from the intentionally transaction-safe, detached diagnostic `preview_due_local_interrupts`. Rust regressions cover suspension, ordering, interleaving and failure boundaries, but no actual game engine state is exposed or mutated by default.
- `script_binding::install_map_scripts` (also exposed by `StaticScene::unstarted_script_runtime`) loads independently owned **unstarted** Rust VMs from each MAP script record resolved via original `scripts.lst`/installed `.INT` files. Every record retains its original category/SID/list metadata and an optional Rust-owned instance ID; missing list entries and missing installed bytecode remain explicit. Two records sharing one `.INT` still have independent mutable VM state. No `start`, `map_enter_p_proc`, spatial trigger, scheduler callback or quest operation is invoked by loading.
- The 24-slot `ScriptRuntime::resolve_action` and `dispatch_action_with` bridge original CE action names to optional local procedure indices and an **opt-in** host callback, never automatically invoking a game procedure. They reject out-of-range slots and missing instances, and leave unimplemented actions unresolved.
- `src/script_lifecycle.rs` plans original CE START, MAP_ENTER, MAP_UPDATE and MAP_EXIT selection without execution, matching source category/record order, map-first updates, the nonzero procedure index check and first-visit parameter. It intentionally omits first-load/start fallback and live engine side effects. Eleven synthetic adapted C++/Rust cases verify decisions.
- `--inspect-map-lifecycle` provides a Linux read-only inspection of planned script actions for an installed MAP, using explicit map SID and flags. Synthetic CLI tests cover inclusion, map-script exclusion and invalid phases.
- `src/script_locals.rs` provides bounded Rust-owned MAP-local state: saved offsets, scripts.lst declarations, lazy zero-filled integer allocation, per-instance bounds, and an out-of-band side array for opaque pointer-tagged i32 handles. As in CE, null pointers read back as integer zero and ordinary integer writes clear pointer tags. Native host addresses are never dereferenced; script opcodes, pointer save/load, full global/quest state and gameplay interactions remain unavailable. Twenty-one adapted C++/Rust synthetic cases pass. `StaticScene::unstarted_script_state` assembles independent VMs plus their local state without executing any game code.
- `src/script_native_vars.rs` implements an **isolated operand-stack adapter** for the four CE `intextra.cc` MAP/local native opcodes `0x80C1`-`0x80C4`. It follows the original pop order, typed return values, invalid-index fallbacks, ignored failed writes and raw non-pointer union bits. It does not hook up `ScriptVm::step` or execute actual INT scripts; 31 adapted C++/Rust synthetic decisions pass.
- `src/game_globals.rs` separately models the Fallout game-wide **GAME_GLOBAL_VARS** integers and detached native opcodes `0x80C5`/`0x80C6`, including the original difference between no variables (-1) and an invalid index in a populated array (0). Sixteen adapted C++/Rust synthetic cases pass. The bounded `game_load_info_vars`-style parser reads the original `data/vault13.gam` defaults through `GameAssets::game_global_defaults`, preferring case-insensitive loose game data with a master DAT fallback. The Linux `--inspect-game-global` command is read-only and has synthetic installation tests. Global quest scripts, runtime mutation by original INT programs and save/load persistence remain unimplemented.
- `ScriptVm::step_with_variable_host` and `run_variable_subset_bounded` provide **explicit-host**, bounded execution of the source-verified CE core/native variable subset; ordinary `step` remains incapable of invoking these game opcodes. Invented core+native bytecode traces independently compare 12 C++/Rust scenarios. Host side effects are not transactionally rolled back on errors; the VM's PC/operand stack remain unchanged on a rejected native callback.
- `ScriptInvocationState` and `run_invocation_subset_bounded` model `exec_script_proc` action assignment, per-invocation `scriptOverrides = 0`, native `op_script_overrides` (0x80B9), `op_script_action` (0x80C7), and `op_fixed_param` (0x80F7). A `PlannedMapAction` can create detached invocation metadata with MAP_ENTER first-visit parameters. Twelve adapted C++/Rust invocation traces pass; the Rust interpreter still does not start real MAP scripts or cause engine effects.
- `StaticScene::unstarted_script_environment` gathers independent decoded MAP script VMs, MAP-local variables, original header lastVisitTime and optional installed `vault13.gam` game-wide defaults. Absence of the latter is explicitly `None`, not silently invented data. Invented Linux installation tests verify the state remains unstarted and original MAP unchanged.
- `src/script_clock.rs` implements explicitly gated CE native `game_time` (0x80EA), `game_time_in_seconds` (0x80EB), `game_ticks` (0x80F2), `game_time_hour` (0x80F6), `get_month` (0x8118), `get_day` (0x8119), and `days_since_visited` (0x811B). The date reproduces original 365-day/December 5, 2161 CE arithmetic rather than Gregorian leap-year rules. The last-visit opcode requires the serialized MAP's independent lastVisitTime, where zero means never visited; omitting this input rejects the native call. Forty-eight adapted C++/Rust synthetic comparisons check times, signed dates, month/year rollover and whole-day differences. Rust rejects unsafe signed-overflow inputs.
- Ten additional adapted C++/Rust synthetic cases compare the original `GAME_GLOBAL_VARS` parser's section matching, signed decimal prefixes, comments, blank lines, and CRLF against the Rust `vault13.gam` decoder.
- `run_invocation_with_clock_bounded` combines detached script action, overrides, `fixed_param`, MAP-local state, game-wide globals and a fixed game clock in an **opt-in**, instruction-bounded Rust VM host. `run_invocation_with_clock_and_visit_bounded` additionally accepts `ScriptClockContext` with optional MAP lastVisitTime for source-faithful `days_since_visited` reads. Eight adapted C++/Rust bytecode comparisons cover first versus repeat entry, empty global arrays, missing SIDs and signed clocks. No real game procedure or host callback is implicitly enabled.
- `src/script_timer.rs` models `script_q_add/save/load/process` via the existing chronological `EventQueue`, preserving original big-endian SID/fixedParam bytes, stable FIFO scheduling, unknown SIDs, owner removal and detached TIMED (action slot 22) plans. Ten adapted C++/Rust synthetic scheduling comparisons pass. Opcodes `add_timer_event` (0x80F0) and `rm_timer_event` (0x80F1) can run through an **explicit caller-owned** queue/object binding host using opaque pointer handles; null objects are no-ops. Actual timer callbacks, persistent save-game dispatch and engine pointer semantics remain unported.
- `ScriptVm::preview_local_interrupt_with_host_bounded` now supports read-only caller-supplied native opcodes inside a synthetic local CE procedure with original setupCall/return-stack and `0x8025` result behavior. The core-only preview stays gated. Fifteen adapted C++/Rust local interrupt decisions, including seven clock-host additions, pass core CI. A mutable host's external side effects cannot be rolled back merely by cloning its VM; use an immutable clock for safe diagnostics.
- `src/script_object_read.rs` implements four **read-only, explicitly hosted** CE native property opcodes: `tile_num` (0x80D4), `elevation` (0x80EC), `obj_pid` (0x8100), and `obj_art_fid` (0x8149). Values come solely from caller-supplied immutable object snapshots associated with opaque integer handles, never native pointers. Null-object return values follow pinned `intextra.cc`; unknown or ambiguous handles error without consuming operands. Twenty synthetic adapted C++/Rust object-property bytecode comparisons and Rust rejection tests passed core CI run 39999029788. `run_invocation_with_native_snapshot_bounded` additionally composes these reads with detached action, MAP-local/quest-global and fixed-clock state; a synthetic mixed bytecode regression passed core CI run 39999702765. The existing clock-only host still rejects object reads when snapshots are not explicitly supplied. Real object identity, scene mutation and unmodified game scripts remain unverified.
- CE `op_tile_contains_obj_pid` (0x80BB) is now a fifth **explicitly hosted read-only** object query. It pops PID, elevation and tile, uses the source objectTable elevation rather than an object's header elevation, and returns an integer presence bit. Twenty invented C++/Rust differential cases passed core CI 40004009967. Normal ScriptVm execution, absent object hosts, invalid operand types, and unknown objects remain guarded. This does not simulate a live world search or original gameplay scripts.
- `PreparedScriptEnvironment::detached_event_for_planned` rejects stale or altered action plans by checking installed VM identity, serialized SID/record position and the actual resolved procedure. `DetachedMapEventSessions` is a separate opt-in map of per-installed-VM event states; a successful normal completion clears source while retaining target/fixed parameter across later planned actions. Its owner fallback is source-derived and refuses unverified spatial/nested owners. Twenty invented C++/Rust event-lifecycle cases and Rust integration tests passed core CI 40012639694. This still does not dispatch original procedures, persist Fallout savegames or execute player/NPC interactions.
- `src/script_event_state.rs` provides a detached, source-derived CE event-participant lifecycle. `scr_set_objs` maps two explicit top-level `ObjectKey` values to snapshot-local pointers; `exec_script_proc` action entry resets overrides, retains `fixedParam`, and falls back from a null target to a source-verified script owner; normal completion clears source only. Ambiguous/spatial/nested owner fallback remains blocked. The state supplies only the opt-in native event host and does **not** execute a script or allocate a game object.
- `src/script_owner_binding.rs` joins MAP script IDs with top-level object script IDs following pinned CE `obj_load_func`/`scr_find_obj_from_program`. It does not use saved owner numeric IDs to guess identity, and rejects duplicate script/object SID claims, bad SID categories and engine-created spatial owners. The pinned `obj_load_obj` also binds scripts on nested inventory objects; because the object-query snapshot intentionally contains only top-level objects, any nested SID claim is reported as unsupported rather than incorrectly becoming NULL or a top-level owner. The explicit-host `self_obj` (0x80BC) produces the resolved pointer or a true non-spatial NULL; it remains denied by ordinary VM execution. Twenty synthetic adapted C++/Rust `self_obj -> tile_num` cases passed core CI 40006876485. The read-only `--inspect-map-script-owners` command prints owner-binding diagnostics without executing scripts.
- `src/script_object_binding.rs` constructs inert, source-derived object-property snapshots from decoded MAP **top-level** objects. Handles are nonzero snapshot-local tokens keyed by `(elevation, ordinal)`, not saved IDs (which may repeat) or native pointers. Nested inventory children are excluded. An unstarted script environment includes this read-only snapshot; `RuntimeScene` can refresh it after movement without changing old snapshots or dispatching scripts. Real-engine pointer identity and gameplay event effects remain out of scope. CI run 40002921218 passed original-format synthetic object-table decoding through explicitly hosted INT bytecode, plus moved-actor snapshot refresh and null/unknown handle tests. This does not verify original installed game content.
- `run_invocation_with_event_snapshot_bounded` implements opt-in, read-only CE `source_obj` (0x80BD), `target_obj` (0x80BE), and target-alias `obj_being_used_with` (0x80C0). The caller must explicitly supply script-event source/target handles, distinguishing absent context from actual NULL pointers; all nonzero handles are checked against detached object snapshots. The ordinary, clock-only, and owner-only hosts reject these event-native opcodes. Twenty adapted C++/Rust source-target comparisons and twelve used-with comparisons passed core CI 40009363950. No Fallout event callback or `scr_set_objs` invocation occurs implicitly.
- `src/script_time_advance.rs` models CE `op_game_time_advance` (0x80FC) as an instruction-budgeted, **nonexecuting** sequence of daily tick increments and queue polls. Synthetic C++/Rust source-derived ordering comparisons pass. No game clock advances, queue processing executes, or MAP update callback runs as a result of producing the plan.
- CI checks Rust tests, lint/format and independent C++ versus Rust *adapted* reference decisions over invented numeric, string/pointer comparison, procedure lookup and scheduler/polling cases. These are not a full compiled upstream CE executable oracle, and do not prove real-game parity.

## Remaining gates

Actual CE conditional expression execution with interpreter stack/flag restoration; imported/exported procedures and external variables; game-specific opcodes and callbacks; schedule-to-engine dispatch; persistent script VM and map/quest state; verified interaction with original legally supplied Fallout 1 content. Full playable Linux compatibility remains a later milestone, and Fallout 2 is out of scope until it passes.
